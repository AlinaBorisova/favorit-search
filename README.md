# Поиск автозапчастей

**Демо:** https://favorit-search.vercel.app

Клиентское приложение на React для поиска автозапчастей и аналогов через API «Проценка» (Фаворит). Тестовое задание.

Поиск идёт в два этапа:

1. Пользователь вводит артикул и получает список производителей, у которых есть деталь с таким номером.
2. После выбора производителя показываются сама деталь и её аналоги: по каждому складу цена, дата отгрузки и остаток.

## Запуск

```bash
npm install
cp .env.example .env
npm run dev
```

В `.env.example` лежат адрес API и тестовый ключ из документации. Для деплоя переменные `VITE_API_URL` и `VITE_API_KEY` нужно задать в настройках хостинга: файл `.env` в репозиторий не попадает.

## Стек

React 19, Redux Toolkit (RTK Query для запросов), Bootstrap 5, Vite. Без TypeScript, как требует задание. Тесты: Vitest и Testing Library. Цвета и шрифт (Roboto) взяты с сайта заказчика и вынесены в CSS-переменные (`src/styles/tokens.css`).

## Структура

```
src/
  app/                 сборка приложения: store
  features/
    parts-search/      фича «поиск запчастей»
      api/             запросы (RTK Query) и обработка ошибок API
      lib/             чистые функции: строки таблицы, группировка, форматы, тексты ошибок
      model/           redux-slice: артикул и выбранный производитель
      ui/              SearchForm, BrandList, OffersSection, OffersTable
      index.js         публичный API фичи
  shared/ui/           общие компоненты: Loader, ErrorAlert
  styles/              токены и переопределения Bootstrap
  test/                настройка тестов
```

Правила импортов: между слоями через алиас `@` и только через `index.js` фичи, внутри одной фичи относительные пути. Экспорты именованные, по умолчанию экспортируются только редьюсер и корневой `App`.

## Принятые решения

- **Запрос по кнопке «Найти» или Enter, а не по мере ввода.** У API есть лимит запросов (`Request quota exceeded!`), поиск при каждом нажатии клавиши быстро его исчерпал бы. Пустой ввод и пробелы не отправляются.
- **Состояние разделено по назначению.** Текст в поле хранится локально в форме; в Redux попадает только отправленный артикул и выбранный производитель; данные с сервера хранит RTK Query и в slice не дублируются.
- **`currentData` вместо `data`.** При новом поиске пользователь не видит список от предыдущего запроса, пока грузится новый.
- **Выбранный производитель сбрасывается при новом поиске,** чтобы выбор от прошлого артикула не попал в новый запрос.
- **Цена берётся из склада (`warehouses[].price`).** Документация API запрещает использовать поле `price` у самого товара.
- **Строка на каждый склад.** У одной детали на разных складах разные цены и сроки отгрузки, поэтому склады показываются отдельными строками, сгруппированными по детали. Склады с нулевым остатком не показываются; если в наличии нет нигде, позиция выводится одной строкой «Нет в наличии» без цены.
- **Порядок в таблице:** искомая деталь, затем аналоги в наличии, затем аналоги без наличия, чтобы цены не терялись среди пустых позиций.
- **Ошибки API приведены к одному виду.** Сервис возвращает ошибки в JSON `{"error": "..."}` и при коде 200, и при 403. Обёртка `withApiErrors` превращает их в `API_ERROR`, а `getErrorMessage` показывает пользователю понятный текст. Состояния загрузки, ошибки и «ничего не найдено» обработаны на обоих этапах.
- **Валюта.** В документации она не указана, цены показываются в рублях (допущение).

## Тесты

Покрыта логика, где проще всего ошибиться, и поведение, которое видит пользователь:

- преобразование ответа API в строки таблицы (цена со склада, склады без остатка, аналоги), группировка и сортировка;
- обработка ошибок API, в том числе с кодом 403, и тексты сообщений;
- `SearchForm`: блокировка кнопки, отправка по клику и по Enter, обрезка пробелов;
- `OffersTable`: данные для позиции в наличии, позиция без наличия, плашка «Искомая», прочерки, доступное имя таблицы.

Компоненты проверяются с настоящим стором: тест смотрит на результат (что лежит в состоянии и что видно на странице), а не на вызов функций.

## Доступность

- У поля поиска есть подпись для скринридера, у таблицы `caption`, у блоков загрузки и ошибки `role="status"` и `role="alert"`.
- Выбранный производитель отмечен атрибутом `aria-pressed`, а не только цветом.
- Интерфейс доступен с клавиатуры. Фокус виден у каждого элемента: у поля цветом рамки, у кнопок кольцом цвета проекта.
- Таблица адаптивна: на узких экранах прокручивается внутри своей рамки.

## Ограничения и возможные доработки

- **Лимит тестового ключа.** У ключа из документации есть ограничение на грузовой ассортимент. Некоторые бренды (например, HAFFEN при поиске `0189`) могут возвращать `Request quota exceeded!`, и приложение показывает это сообщением, а не пустой страницей.
- **Ключ API в клиентском коде.** Переменные `VITE_*` попадают в браузерный бандл. Для тестового ключа это допустимо; в боевом приложении запросы шли бы через серверный прокси.
- **Не используются** признак невозвратной позиции (`info=on`, `notRefund`) и кратность (`rate`): задание их не требует.
- **Можно добавить:** сортировку и фильтры таблицы, e2e-тесты.
